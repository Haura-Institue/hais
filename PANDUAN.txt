Panduan pemasangan dan pemakaian | 10 November 2026

01. HASIL REVISI DAN BATAS PENGGUNAAN

Versi ini mengganti seluruh ketergantungan Firebase. Tidak perlu Firebase Console, API key, service account, SQL, bucket, atau instalasi terminal. Website statis berada di GitHub Pages. Google Drive menyimpan data; Google Apps Script menjadi penghubung agar database tidak dibuka publik.

Login tersedia dengan email + password akun Haura. Email hanya identitas login, bukan Google Sign-In dan bukan bukti kepemilikan alamat email. Tidak ada verifikasi email atau email reset. Peserta mendaftar, statusnya pending, lalu admin mengaktifkan. Admin wajib memeriksa identitas pendaftar lewat kanal resmi sebelum menyetujui.

Pengaturan awal hanya:
• Tiga Script Properties di Apps Script: SITE_ORIGIN, ADMIN_EMAIL, ADMIN_PASSWORD.
• Satu URL deployment di website: js/drive-config.js.
• Aktifkan Pages melalui Settings repository; tidak perlu membuat workflow, Secrets, Variables, atau service-account key.

Folder Drive, database, dan admin pertama dibuat otomatis saat fungsi siapkanHaura_ dijalankan. Password awal dihapus dari Script Properties sesudah persiapan berhasil. Tidak ada akun admin/password default dalam paket produksi.

PENTING TENTANG GITHUB PAGES: layanan ini bukan hosting gratis untuk menjalankan bisnis online, e-commerce, SaaS komersial, atau situs yang terutama memfasilitasi transaksi komersial. GitHub juga memperingatkan penggunaan untuk transaksi sensitif seperti pengiriman password/kartu kredit. Karena itu versi ini adalah portal pembelajaran nontransaksi: QRIS/pembayaran tidak tersedia, program gratis, dan formulir akun dilayani pada origin Google Apps Script, bukan formulir password halaman GitHub. Token sesi tetap diperlukan oleh antarmuka portal. Pemisahan formulir ini BUKAN jaminan semua penggunaan aplikasi otomatis sesuai kebijakan GitHub. Bila tujuan utama Anda menjual pelatihan, menerima pembayaran, atau memproses data sensitif, jangan jadikan versi Pages ini sistem produksi komersial; gunakan penyedia hosting yang mengizinkan kebutuhan tersebut.

Tampilan, logo, katalog, berita, validasi admin, modul, sertifikat/PDF, diskusi, dan latihan SOAP dipertahankan/disesuaikan. Foto peserta opsional, tidak wajib saat pendaftaran. Chat dibuka bersamaan saat admin mengaktifkan akun. Versi ini tidak menyertakan payment gateway, QRIS, notifikasi push, atau rekam medis.

Paket BELUM dipasang pada akun Anda. Placeholder URL memang belum diisi. Pengujian lokal tidak sama dengan pengujian Google Apps Script dan GitHub Pages yang sebenarnya. Ikuti checklist bagian 16 sebelum menerima peserta nyata.

02. PERSIAPAN SINGKAT

1. Siapkan akun GitHub dan satu akun Google yang memiliki ruang Drive. Akun Google khusus institusi lebih disarankan daripada akun Drive pribadi berisi dokumen penting.
2. Aktifkan verifikasi dua langkah akun Google dan GitHub. Jangan berbagi password pengelola dengan peserta.
3. Ekstrak ZIP ini. Buka folder haura-institute. Jangan upload ZIP sebagai pengganti isi website.
4. Kerjakan pemasangan awal menggunakan laptop/PC agar salin kode lebih mudah. Tidak perlu Node, Git, Firebase CLI, Python, atau terminal di perangkat Anda.
5. Simpan ZIP asli sebagai cadangan. Gunakan panduan versi 3 ini saja; jangan mencampur langkah panduan Firebase sebelumnya.

File penting:
index.html = halaman utama; assets/ = logo/desain; js/app.js = antarmuka.
js/backend.js dan js/drive-client.js = penghubung data; tidak perlu diedit untuk pemasangan biasa.
js/drive-config.js = SATU URL yang Anda isi.
apps-script/Code.gs = SATU kode server lengkap yang Anda salin ke Apps Script.
PANDUAN.html / PANDUAN.txt / PANDUAN.pdf = panduan ini.
MULAI-DI-SINI.txt = ringkasan urutan. HASIL-UJI.txt = cakupan tes.
.nojekyll = menandai website statis biasa di GitHub Pages.
vendor/pdf.js = pustaka PDF sertifikat; jangan dihapus.
tests/ = tes lokal opsional untuk pengembang; peserta tidak perlu menjalankannya.

Tidak ada firebase.json, SDK Firebase, folder Supabase, atau langkah pengaturan Firebase dalam versi ini. File uji berisi kredensial contoh untuk simulator; bukan akun nyata dan jangan dijadikan password produksi.

03. BUAT REPOSITORY GITHUB TERLEBIH DAHULU

1. Buka https://github.com/ dan masuk.
2. Klik tombol + > New repository.
3. Nama repository, misalnya haura-institute. Gunakan huruf kecil dan tanda hubung agar sederhana.
4. Pilih Public. Pada GitHub Free, Pages tersedia untuk repository public. Jangan mengunggah data peserta atau password karena seluruh kode akan terlihat publik.
5. Centang Add a README file untuk membuat branch main, lalu Create repository.
6. Catat username GitHub dan nama repository. Contoh: username ahmadhaura, repository haura-institute.
7. Alamat website biasanya https://ahmadhaura.github.io/haura-institute/ . Ini contoh, ganti dengan akun Anda.
8. ORIGIN yang dibutuhkan server hanya https://ahmadhaura.github.io . Jangan sertakan /haura-institute/ dan jangan tambahkan slash terakhir pada origin.
9. Jangan mengaktifkan Pages dulu jika belum mengunggah file; kita akan mengaktifkannya setelah backend siap.

Repository PUBLIC berisi kode dan satu URL Apps Script saja. Password admin berada sementara dalam pengaturan server privat. Database yang berisi akun/hash password/sesi/percakapan tidak boleh masuk repository, bahkan repository private sekalipun.

04. SALIN SATU FILE KE APPS SCRIPT

1. Buka https://script.google.com/ dengan akun Google pengelola.
2. Klik New project / Proyek baru.
3. Beri nama Haura Drive Sederhana.
4. Di editor ada Code.gs dengan kode contoh. Hapus seluruh kode contoh.
5. Buka file apps-script/Code.gs dari ZIP dengan editor teks. Salin SELURUH isinya, termasuk bagian pustaka kriptografi yang panjang.
6. Tempelkan seluruhnya ke Code.gs di website Apps Script. Simpan dengan Ctrl+S atau ikon Save.
7. Tidak perlu membuat file HTML terpisah. Formulir akun dan pustaka hash sudah disertakan dalam Code.gs tersebut.
8. Tidak perlu mengganti nilai password di dalam kode. Semua konfigurasi dilakukan pada Script Properties di bagian berikut.
9. Tidak perlu mengatur manifest JSON, Google Cloud credentials, Firebase, atau API key.

Jangan menghapus baris pustaka minified karena dianggap membingungkan: baris itu diperlukan untuk hashing password. Kode server memakai PBKDF2-HMAC-SHA256 600.000 iterasi dengan salt berbeda tiap akun. Hash bukan password teks biasa, tetapi file database tetap sangat rahasia dan tidak boleh dibagikan.

05. ISI TIGA SCRIPT PROPERTIES

1. Di kiri Apps Script klik Project Settings / ikon roda gigi.
2. Temukan Script Properties, klik Add script property.
3. Buat tiga baris dengan nama persis di bawah. Huruf besar dan underscore penting.

SITE_ORIGIN
Nilai: https://USERNAME_ANDA.github.io
Contoh: https://ahmadhaura.github.io
Tanpa nama repository, tanpa path, tanpa slash akhir. Gunakan username huruf kecil. Untuk pemasangan standar ini jangan memakai localhost, alamat repository github.com, atau URL Apps Script.

ADMIN_EMAIL
Nilai: alamat yang akan dipakai login admin, misalnya pengelola@institusi.id.
Alamat harus berbentuk email yang benar. Tidak ada email yang dikirim, tetapi gunakan alamat asli institusi agar identitas jelas.

ADMIN_PASSWORD
Nilai: password admin yang ANDA pilih, minimal 10 sampai maksimal 128 karakter. Disarankan frasa panjang unik dan tidak dipakai pada akun lain. Ini bukan password akun Google dan bukan password GitHub.
Jangan menyalin password contoh dari file tests. Simpan password pilihan Anda dalam pengelola password pribadi.

4. Klik Save script properties.
5. Jangan menambahkan DRIVE_FOLDER_ID atau DB_FILE_ID manual; keduanya akan dibuat otomatis.
6. Jangan screenshot/unggah isi ADMIN_PASSWORD ke GitHub atau chat publik. SITE_ORIGIN bukan rahasia, tetapi password tetap rahasia.

Setelah setup berhasil, ADMIN_PASSWORD dihapus otomatis dari Script Properties; database hanya menyimpan hash password. ADMIN_EMAIL dan SITE_ORIGIN tetap ada. Untuk pemulihan admin yang lupa password, gunakan bagian 12.

06. JALANKAN PERSIAPAN OTOMATIS SEKALI

1. Kembali ke Editor Apps Script.
2. Di dropdown fungsi dekat tombol Run, pilih siapkanHaura_. Tanda underscore di akhir adalah bagian nama.
3. Klik Run / Jalankan.
4. Jika diminta izin, pilih Review permissions lalu akun Google pengelola.
5. Periksa kode serta izin Drive yang diperlukan. Script harus dapat membuat/membaca/menulis file Drive milik pengelola. Karena akses Drive cukup luas, akun khusus institusi lebih aman.
6. Pada script milik sendiri yang belum diverifikasi, Google dapat menampilkan peringatan. Lanjutkan melalui Advanced hanya jika Anda memahami dan mempercayai kode ini. Jika diblokir kebijakan Workspace/organisasi, jangan mencoba memaksa melewatinya; gunakan akun yang diizinkan atau minta peninjauan administrator.
7. Tunggu sampai selesai. Hashing password memang dapat memerlukan beberapa detik; jangan klik Run berulang kali.
8. Hasil yang diharapkan pada Execution log: SIAP. Folder HAURA-DATABASE-PRIVAT dan database dibuat; password awal dihapus dari Script Properties.
9. Buka https://drive.google.com/ . Akan ada folder HAURA-DATABASE-PRIVAT dengan haura-database.json di dalamnya.
10. Klik kanan folder > Share / Bagikan. Pastikan General access: Restricted / Dibatasi. Jangan bagikan folder database ke peserta atau Anyone with the link.
11. Kembali ke Script Properties. DRIVE_FOLDER_ID dan DB_FILE_ID sekarang ada otomatis; ADMIN_PASSWORD sudah dihapus.

Setup yang dijalankan lagi setelah DB_FILE_ID ada tidak mengosongkan data atau mengganti admin. Jangan menghapus properti ID untuk mengatasi error biasa; Anda dapat membuat database baru yang terpisah dan mengira data lama hilang. Jangan membuat salinan database bernama sama sebagai pengganti file asli.

07. TERBITKAN APPS SCRIPT SEBAGAI WEB APP

1. Klik Deploy > New deployment di kanan atas editor.
2. Pada pilihan jenis/ikon roda gigi, pilih Web app.
3. Isi deskripsi Haura versi GitHub Drive.
4. Execute as / Jalankan sebagai: Me / akun Google Anda.
5. Who has access / Yang memiliki akses: Anyone / Siapa saja. Bukan Only myself dan bukan hanya anggota organisasi.
6. Klik Deploy. Beri izin tambahan jika diminta.
7. Salin Web app URL yang berakhir /exec.
8. Jangan menyalin URL /dev atau alamat editor script.google.com/home/projects/....
9. Buka URL /exec langsung untuk pemeriksaan. Pesan penghubung aktif adalah normal; database dan formulir login tidak dibuka tanpa origin/channel dari website.

Anyone berarti endpoint dapat dijangkau pengunjung. Data privat tetap memerlukan sesi dan pemeriksaan server. Folder Drive tidak menjadi publik. Katalog/berita/pengaturan beranda yang diterbitkan memang bersifat publik.

Jika Anyone tidak tersedia, kebijakan akun Workspace mungkin melarangnya. Akun Only myself tidak akan bekerja bagi peserta. Hal ini tidak dapat diperbaiki dengan mengubah index.html saja.

08. ISI SATU URL DI WEBSITE

1. Buka js/drive-config.js di folder hasil ekstrak.
2. Ganti teks ISI_URL_WEB_APP_APPS_SCRIPT_EXEC dengan URL /exec dari bagian 07.
3. Bentuk akhirnya seperti berikut, dengan deployment ID milik Anda:

export const driveConfig = {
  webAppUrl: 'https://script.google.com/macros/s/ID_DEPLOYMENT_ANDA/exec',
  pollMs: 30000
};

4. Pertahankan tanda petik lurus, koma, dan kurung. Simpan sebagai drive-config.js, bukan drive-config.js.txt.
5. Jangan isi password admin, email admin, API key, atau ID folder Drive dalam file publik ini. Hanya URL /exec yang dibutuhkan.
6. pollMs 30000 berarti sekitar 30 detik. Jangan turunkan ke satu detik; itu memboroskan pemrosesan Drive/Apps Script.

Itu satu-satunya file konfigurasi website yang perlu Anda ubah untuk pemasangan dasar.

09. UPLOAD DAN AKTIFKAN GITHUB PAGES TANPA TERMINAL

1. Buka repository GitHub tadi, pilih Add file > Upload files.
2. Dari folder haura-institute yang sudah diekstrak, pilih ISI foldernya dan seret ke halaman upload.
3. Jangan menyeret ZIP sebagai satu file. Jangan menyeret folder pembungkus sehingga index.html berada di haura-institute/index.html dalam repository.
4. Root repository harus langsung berisi index.html, assets/, js/, vendor/, manifest.webmanifest, sw.js, dan .nojekyll. File panduan dan kode server boleh disertakan karena tidak berisi kredensial nyata.
5. Jangan upload file haura-database.json, backup, screenshot pengaturan server, token, atau password apa pun. .gitignore tidak menjamin upload web yang Anda lakukan manual akan disaring.
6. Klik Commit changes ke branch main.
7. Pastikan js/drive-config.js di GitHub sudah berisi URL asli, bukan placeholder.
8. Periksa .nojekyll. Jika file bertitik tidak ikut diunggah, Add file > Create new file, namai .nojekyll, isi satu baris kosong, lalu Commit.
9. Buka Settings repository > Pages.
10. Pada Build and deployment, Source pilih Deploy from a branch.
11. Branch pilih main dan folder pilih / (root), lalu Save.
12. Anda tidak perlu menulis YAML workflow, membuat GitHub Secret, membuat service account, atau memasang terminal. GitHub mungkin menampilkan pekerjaan Pages bawaan di tab Actions; itu proses internal penerbitan Pages yang normal.
13. Tunggu sampai Pages menampilkan alamat Your site is live at .... Waktu penerbitan bervariasi; tunggu indikator selesai, bukan menganggap sudah terbit tepat setelah Save.
14. Buka alamat website yang diberikan. Gunakan alamat github.io/REPOSITORY/, bukan alamat kode github.com/USER/REPOSITORY.
15. Aktifkan Enforce HTTPS jika tersedia. Domain github.io standar menggunakan HTTPS.
16. Cocokkan SITE_ORIGIN dengan bagian https://USER.github.io dari alamat sebenarnya. Nama repository tidak masuk SITE_ORIGIN.

Jangan membuka index.html dengan file:// untuk mencoba login. Panduan HTML boleh dibuka langsung, tetapi aplikasi harus melalui alamat HTTPS Pages. Jangan memasukkan password admin ke halaman konfigurasi yang berada di GitHub.

10. LOGIN ADMIN DAN ISI KONTEN

1. Buka alamat Pages > Masuk Portal.
2. Formulir akun akan muncul di bingkai Google Apps Script. Password diisikan di dalam formulir tersebut, bukan field password buatan halaman GitHub. Jangan memasukkan password Google/GitHub; gunakan password admin Haura dari Script Properties awal.
3. Isi ADMIN_EMAIL dan password pilihan Anda. Klik Masuk, tunggu pemeriksaan selesai.
4. Harus muncul PUSAT KENDALI ADMIN. Anda tidak perlu mendaftar admin lagi atau menunggu email.
5. Buka CMS Web. Isi brand, judul beranda, deskripsi, lalu Simpan Pengaturan.
6. Jika ingin video, gunakan URL berkas HTTPS langsung MP4/WebM yang memang boleh diakses publik. Halaman YouTube atau link preview Drive bukan URL berkas langsung. Video opsional; biarkan kosong agar lebih sederhana.
7. Tambah Program Gratis: nama dan deskripsi. Harga tidak diisi karena versi GitHub ini tidak menjalankan transaksi.
8. Tambah berita: judul dan isi, lalu Publikasikan Berita.
9. Untuk edit program, gunakan Edit. Arsipkan menyembunyikan dari publikasi, bukan menghapus seluruh riwayat peserta.
10. Halaman publik menampilkan program/berita tanpa login. Buka melalui browser lain untuk mengecek.

Jangan mengisi nama pasien, identitas klinis, rahasia institusi, atau berkas privat dalam pengaturan beranda/konten publik. Pemisahan akses aplikasi tidak bisa melindungi data yang sengaja diterbitkan sebagai konten publik.

11. PESERTA MENDAFTAR DAN ADMIN MENGAKTIFKAN

1. Peserta membuka website > Pendaftaran.
2. Isi nama, instansi, email sebagai identitas akun, password minimal 10 karakter, ulangi password, dan persetujuan.
3. Klik Daftar & Tunggu Admin. Tidak ada email verifikasi yang dikirim.
4. Peserta langsung bisa melihat Status Pendaftaran, tetapi belum bisa mengakses fitur belajar privat.
5. Di admin buka Validasi Data. Bila pendaftar baru belum muncul, tunggu pembaruan sekitar 30 detik saat tab admin terlihat. Data Anda sendiri setelah menyimpan diambil ulang segera; perubahan pengguna lain memakai polling.
6. Cocokkan email/nama peserta dengan daftar resmi atau kontak yang sudah diverifikasi. Tanpa verifikasi email otomatis, orang dapat mengetik alamat orang lain. Jangan mengaktifkan hanya berdasarkan kemiripan nama.
7. Klik Aktifkan Akun. Status menjadi approved dan akses diskusi dibuka bersama.
8. Di peserta klik Periksa Status atau tunggu polling. Katalog Pelatihan, Modul Saya, Sertifikat, dan Diskusi Profesional tersedia setelah approved.
9. Nonaktifkan pada panel admin mengubah status menjadi rejected dan menutup akses fitur privat berikutnya. Konten yang sudah dilihat/diunduh peserta sebelumnya tidak dapat ditarik kembali.
10. Foto opsional: peserta klik Foto pada navigasi, pilih JPG/PNG/WebP maksimal 5 MB. Jangan mengunggah foto pasien.
11. Peserta dapat klik Ikuti Program untuk mendaftar program yang dipublikasikan. Tidak ada langkah pembayaran atau bukti transfer.

Email yang sudah dipakai tidak dapat didaftarkan ulang dengan variasi huruf besar/kecil. Bila lupa password, jangan membuat akun duplikat; gunakan proses reset admin di bagian berikut.

12. PASSWORD, SESI, DAN PEMULIHAN

Ganti password sendiri:
Klik Ganti Password di navigasi setelah login. Masukkan password saat ini dan password baru yang berbeda, lalu konfirmasi. Formulir diproses pada Apps Script. Setelah berhasil, sesi lama dicabut dan tab ini menerima sesi baru.

Peserta lupa password:
1. Peserta menghubungi pengelola lewat kontak resmi institusi. Tidak ada nomor kontak palsu/default dalam aplikasi.
2. Admin wajib memastikan identitas pemohon melalui kontak yang sudah diketahui, bukan hanya email yang diketik di pesan baru.
3. Admin > Validasi Data > Reset Password pada akun peserta yang benar.
4. Konfirmasi Buat Password Sementara. Aplikasi menampilkan password sementara hanya pada hasil ini.
5. Salin dan kirim secara privat melalui kontak yang sudah diverifikasi. Jangan kirim di grup atau menaruhnya di repository.
6. Seluruh sesi peserta sebelumnya dicabut. Peserta login dengan password sementara; aplikasi mewajibkan perubahan sebelum membuka data portal.
7. Pada layar Ganti Password, masukkan lagi password sementara, password baru, dan konfirmasinya. Setelah berhasil, password sementara tidak berlaku lagi.

Admin lupa password:
1. Pemilik akun Google membuka proyek Apps Script, bukan halaman GitHub.
2. Project Settings > Script Properties. Pastikan ADMIN_EMAIL cocok dengan admin yang dibuat sebelumnya.
3. Tambahkan ADMIN_PASSWORD berisi password pengganti minimal 10 karakter, Save.
4. Editor > pilih pulihkanAdmin_ > Run. Tunggu selesai.
5. Password admin diperbarui, sesi admin lama dicabut, dan ADMIN_PASSWORD dihapus lagi. Tidak perlu deploy ulang karena yang berubah data, bukan kode.
6. Kembali ke website dan login dengan password baru. Fungsi pemulihan ini tidak bisa dipanggil melalui google.script.run karena helper server berakhiran underscore.

Sesi hanya disimpan di memori tab, tidak di localStorage/sessionStorage. Refresh halaman atau menutup tab memerlukan login lagi. Sesi server maksimal 8 jam dan paling banyak 5 sesi aktif per akun. Keluar mencabut sesi tab itu. Ini pilihan sederhana untuk tidak menyimpan token di penyimpanan browser; bukan fitur “ingat saya”.

Ada pembatasan percobaan: sampai 10 percobaan akun dalam jendela 15 menit sebelum ditahan; login/pendaftaran yang berhasil membersihkan penghitung emailnya. Pendaftaran global dibatasi 12 per jam dan operasi autentikasi global dibatasi per menit. Ini perlindungan dasar, bukan anti-DDoS. Jika ada penggunaan serentak besar atau serangan, layanan bisa tetap sibuk/kehabisan kuota. Jangan mengurangi parameter hash agar login tampak lebih cepat.

13. MODUL, SERTIFIKAT, DAN DISKUSI

Modul:
1. Admin > Distribusi Modul, isi judul dan URL HTTPS dokumen.
2. Pilih peserta atau Semua Peserta Disetujui, lalu simpan.
3. Peserta membuka Modul Saya. Fitur membagikan link, bukan otomatis mengunggah PDF.
4. Jika dokumen berada di Drive dan terbatas, Share dokumen modul itu ke akun Google peserta sebagai Viewer. Peserta perlu login Google saat membuka dokumen eksternal. Akun Haura tidak otomatis mengubah izin dokumen Google.
5. Anyone with the link hanya untuk materi yang memang boleh diteruskan. JANGAN bagikan folder HAURA-DATABASE-PRIVAT.

Sertifikat:
1. Admin > Sertifikat, pilih peserta approved, isi program, nomor, tanggal, dan penandatangan yang sah.
2. Logo utama bawaan dipertahankan. Tambahkan logo mitra/tanda tangan hanya bila memiliki hak penggunaannya.
3. Unduh Preview PDF untuk memeriksa hasil.
4. Terbitkan & Kirim Sertifikat menyimpan gambar sertifikat privat di Drive dan metadata pemilik.
5. Peserta membuka Sertifikat dan mengunduh PDF. Jika gambar terlalu besar, kurangi ukuran logo/tanda tangan; batas unggah 5 MB.
6. Ini dokumen visual, bukan tanda tangan elektronik tersertifikasi atau jaminan akreditasi otomatis.

Diskusi:
1. Akses chat aktif ketika admin mengaktifkan akun.
2. Peserta > Diskusi Profesional, tulis pesan atau latihan SOAP.
3. Admin > Chat Berkala, pilih peserta untuk membalas.
4. Pesan pengguna lain tampil sekitar 30 detik saat tab terlihat; tidak ada push notification atau jaminan realtime.
5. Jangan memasukkan nama pasien, NIK, nomor rekam medis, alamat, foto, atau informasi yang bisa mengidentifikasi pasien. Gunakan kasus simulasi/anonim. Portal ini bukan sistem rekam medis atau layanan darurat.

14. UPDATE, BACKUP, DAN DATA VERSI LAMA

Update website:
Edit file di GitHub melalui ikon pensil, Commit changes ke main, lalu tunggu penerbitan Pages selesai. Naikkan VERSION di sw.js, misalnya haura-v3.0.0-github-drive menjadi haura-v3.0.1-github-drive. Simpan pekerjaan sebelum menerima pembaruan PWA. Mengubah file lokal tanpa mengunggah/commit tidak mengubah website.

Update backend:
Simpan perubahan Code.gs di Apps Script, lalu Deploy > Manage deployments > Edit deployment lama > New version > Deploy. Save saja tidak mengganti versi /exec produksi. Gunakan deployment lama agar URL tetap sama. Jika URL berubah, perbarui js/drive-config.js di GitHub dan naikkan VERSION service worker.

Backup:
1. Di editor Apps Script jalankan backupOwner_. Backup JSON dibuat dalam folder database yang sama.
2. JSON versi ini berisi profil, hash password, salt, metadata sesi, dan referensi file. Perlakukan seluruh backup sebagai rahasia setara database. Jangan upload backup ke GitHub.
3. Backup JSON bukan salinan fisik semua foto/sertifikat. Unduh juga berkas/folder yang diperlukan dan simpan konfigurasi server secara aman.
4. Menyalin berkas ke folder Drive lain menghasilkan ID baru; referensi JSON tidak otomatis berubah.
5. Jangan memulihkan dengan mengunggah file JSON kedua bernama sama. Pemulihan harus mempertahankan ID database asli dan mencocokkan file yang dirujuk; minta bantuan teknis jika tidak yakin.
6. Backup di akun Drive yang sama tidak melindungi dari kehilangan akun. Siapkan cadangan terpisah yang aman sesuai kebijakan institusi.

Data versi sebelumnya:
Paket ZIP lama berisi kode, bukan semua data cloud Anda. Akun/password Firebase tidak otomatis menjadi akun lokal Drive; password Firebase tidak dapat dibaca untuk dikonversi. Gunakan pendaftaran baru dan validasi admin, atau rencanakan migrasi data nonpassword secara terpisah. Jangan menghapus data/layanan lama sebelum backup dan pencocokan selesai. Bila belum ada data nyata, mulai database baru lebih sederhana.

15. BATAS GRATIS DAN TROUBLESHOOTING

GitHub Pages dan layanan Google memiliki ketentuan serta kuota, bukan gratis tanpa batas. Gunakan domain github.io bawaan; domain khusus dapat berbiaya. Akun Google pribadi umumnya memiliki ruang bersama Drive/Gmail/Photos; pastikan masih tersedia. Apps Script membatasi runtime, akses layanan, serta konkurensi. Tidak ada Firebase/UrlFetch pemeriksaan token pada versi ini, tetapi pembacaan Drive dan komputasi hashing tetap mengonsumsi sumber daya.

Batas aplikasi: unggahan 5 MB; database JSON 3 MB; polling default 30 detik. Seluruh JSON dibaca pada snapshot sehingga model ini cocok untuk beban kecil, bukan portal besar. Tidak ada SLA, antivirus menyeluruh, audit log tak dapat diubah, enkripsi end-to-end, backup otomatis, atau audit keamanan independen. Data sensitif/rekam medis tidak sesuai untuk versi ini. Ketika kuota habis, fitur bisa gagal; jangan menjanjikan ketersediaan tanpa batas.

Mode persiapan muncul:
Periksa js/drive-config.js di GitHub, URL /exec, commit terakhir, dan cache PWA. Pastikan bukan file .js.txt. Naikkan VERSION saat memperbarui.

Penghubung tidak merespons / formulir kosong:
Periksa SITE_ORIGIN persis https://USER.github.io tanpa nama repository/slash, deployment Me + Anyone, versi kode terbaru, izin pemilik, dan kebijakan browser. Uji Chrome biasa tanpa pemblokir lebih dahulu. Google Apps Script memakai iframe; pembatasan browser/Workspace/Google dapat membuatnya gagal. Jangan mengatasi dengan membuat folder database publik. Pengujian live tetap wajib.

Halaman GitHub 404:
Pastikan repository public, Pages main / (root), dan index.html ada langsung di root. Buka URL github.io/nama-repository/, bukan URL kode github.com. Tunggu proses Pages selesai.

Admin tidak bisa login:
Pastikan setup selesai dan menggunakan ADMIN_EMAIL/password Haura yang Anda pilih, bukan password Google/GitHub. Jangan mendaftarkan ulang email admin. Gunakan pulihkanAdmin_ jika lupa. Jika perhitungan sedang berjalan tunggu; jangan klik berulang kali.

Peserta belum aktif:
Admin klik Aktifkan Akun. Peserta klik Periksa Status. Email memang tidak diverifikasi otomatis; jangan menunggu email yang tidak dikirim.

Terlalu banyak percobaan:
Tunggu hingga batas waktu selesai; jangan berulang-ulang mengganti password. Pengelola dapat mereset peserta melalui alur resmi setelah verifikasi identitas. Jangan menghapus seluruh database untuk membuka pembatasan.

Modul meminta izin:
Atur sharing DOKUMEN MODUL dan akun Google peserta. Izin modul eksternal berbeda dari aktivasi akun Haura. Jangan bagikan folder database.

Unggah gagal:
Gunakan JPG/PNG/WebP valid maksimal 5 MB, akun yang sesuai, ruang Drive tersedia, dan file fisik tidak terhapus. SVG/HEIC/PDF tidak didukung untuk kolom gambar. Pemeriksaan signature dasar bukan antivirus.

Operasi melewati batas waktu:
Operasi mungkin sudah tersimpan walaupun balasan terlambat. Periksa data sebelum mengulang untuk menghindari duplikasi. Tidak ada retry tulis otomatis.

Website lama masih tampil:
Tunggu penerbitan Pages, naikkan VERSION sw.js, tutup PWA/tab lama, dan buka lagi. Sesi memang hilang saat reload. Kerangka PWA bisa offline, tetapi login/database/chat/modul privat membutuhkan internet.
